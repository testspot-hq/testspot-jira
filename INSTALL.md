# Панель TestSpot в Jira Data Center — установка

Инструкция для администратора. Две стороны: плагин на Jira и три переменные на стенде TestSpot.
Обычно это один человек, но если разные — обе половины нужны, по отдельности не работает ни одна.

Что вы получили в архиве:

| | |
|---|---|
| `testspot-jira-panel-<версия>.jar` | плагин для Jira Data Center / Server |
| `INSTALL.md` | этот же текст |
| `sha256sum.txt` | контрольная сумма jar |

Времени: около пятнадцати минут, из них большая часть — перезапуск Jira.

## Что делает плагин, а что нет

Плагин **не показывает данные и не ходит в TestSpot**. Он делает ровно две вещи: ставит на страницу
тикета iframe и подписывает его адрес — чтобы TestSpot мог доказуемо знать, какая это Jira и кто в ней
сейчас смотрит. Всё остальное — сама панель — грузится браузером пользователя прямо со стенда TestSpot.

Из этого следуют два практических факта:

- **Серверу Jira доступ к TestSpot не нужен.** Исходящих запросов из Jira плагин не делает, подпись
  считает локально. Правила фаервола для Jira менять не надо.
- **Браузер каждого пользователя должен видеть хост TestSpot по HTTPS.** Если стенд доступен только из
  VPN, то и панель работает только из VPN — в тикете будет пустой прямоугольник.

## Что нужно заранее

- Jira Data Center или Server **9.12 и новее** — линии 10.x и 11.x включительно — и права
  **Jira system administrator** (без них в меню нет «Upload app»).

  Собран плагин против API Jira 9.12, и намеренно против старой: сборка против свежей LTS закрыла бы
  те инстансы, что ещё на 9.x и 10.x, а обратная совместимость у Atlassian работает в эту сторону.
  Совместимость здесь решается не версией сборки, а тем, какими вызовами плагин пользуется, — их пять
  (`ContextProvider`, `JiraAuthenticationContext`, `ApplicationProperties` + server ID, ключ
  пользователя, ключ тикета), и все они на месте и в 11.x. Манифест OSGi генерирует сама Jira при
  установке, без привязки к версии; байткод — Java 8, он идёт на JVM 17 и 21 без пересборки.
  Фронтендовых ресурсов у плагина нет вообще (панель — iframe), поэтому смены React, jQuery и AUI в
  10.x и 11.x его не касаются.
- Стенд TestSpot, доступный пользователям по HTTPS.
- **Общий секрет**, минимум 32 символа. Сгенерировать:

  ```bash
  openssl rand -base64 32
  ```

  Одно и то же значение уходит в два места: `-Dtestspot.panel.secret` на Jira и
  `PANEL_CONTEXT_SECRET_DC` на TestSpot. Секрет короче 32 символов TestSpot откажется использовать —
  и промолчит в панели, сказав об этом только в лог.

## Шаг 1. Сторона TestSpot

Три переменные. Дефолты выбраны так, чтобы ненастроенный стенд был закрыт, а не «случайно открыт», —
поэтому пропущенная переменная выглядит как неработающая панель, а не как работающая небезопасно.

| Переменная | Значение | Helm (`values.yaml`) | Если не задать |
|---|---|---|---|
| `PANEL_CONTEXT_SECRET_DC` | тот же секрет, что у плагина | `secrets.panelSecretDc` | панель рисуется, но Connect отвечает **503** «not configured for Data Center» |
| `JIRA_FRAME_ANCESTORS` | origin'ы вашей Jira через пробел, например `https://jira.acme.kz` | `frontend.jiraFrameAncestors` | дефолт `'none'` — браузер отказывается встраивать, в тикете пустой прямоугольник |
| `APP_BASE_URL` | внешний адрес TestSpot | `app.baseUrl`, пусто → `https://<ingress.host>` | вне Helm ссылки из панели уйдут на первый origin из списка CORS, то есть куда попало |

`JIRA_FRAME_ANCESTORS` — это **origin**, а не URL: схема, хост и порт, если он нестандартный, без
завершающего слэша и без пути. Несколько Jira — несколько значений через пробел. Пустая строка не
годится: `frame-ancestors` без источников — невалидная директива, которую браузер выбросит вместе с
самим запретом, поэтому дефолт `'none'`, а не пусто.

После правки перезапустите контейнеры `api` и `frontend`. Проверка — одной командой, до всякой Jira:

```bash
curl -sI https://testspot.example.com/embed/jira/ | grep -i content-security-policy
# ожидается: Content-Security-Policy: frame-ancestors https://jira.acme.kz
```

Если в ответе `frame-ancestors 'none'` — переменная не доехала до nginx, и дальше идти незачем.

## Шаг 2. Установить плагин

⚙ (**Administration**) → **Manage apps** → **Manage apps** → **Upload app** → выберите jar.

Дальше плагин виден в **User-installed apps** как **TestSpot Jira panel**, ключ
`kz.testspot.testspot-jira-panel`. Лицензия не нужна, Marketplace не участвует.

## Шаг 3. Две системные свойства JVM

```
-Dtestspot.panel.baseUrl=https://testspot.example.com
-Dtestspot.panel.secret=<секрет из «Что нужно заранее»>
```

Свойства, а не экран настроек: секрет тогда не лежит в базе Jira, а живёт там же, где остальная
конфигурация этого инстанса. Обе обязательны; если любой не хватает, панель пишет в тикете, что не
настроена, и ничего не падает.

Оба значения — это аргументы **JVM, под которой работает Jira**, а не настройка приложения: ни в
интерфейсе Jira, ни в файлах TestSpot их вписать нельзя. Место зависит от того, как Jira поставлена.

**Установщик или tar.gz (Linux).** Файл `<каталог-установки>/bin/setenv.sh` — по умолчанию
`/opt/atlassian/jira/bin/setenv.sh`. Там есть строка вида `JVM_SUPPORT_RECOMMENDED_ARGS=""`; в неё, через
пробел, и добавляются оба аргумента:

```sh
JVM_SUPPORT_RECOMMENDED_ARGS="-Dtestspot.panel.baseUrl=https://testspot.example.com -Dtestspot.panel.secret=RvE1s0kK7mQpZ2xL9dTn4uWbY6hJ8aCf"
```

Кавычки — вокруг всего значения, один раз. Если в переменной уже что-то стоит, дописывайте к
существующему, а не заменяйте: там могут быть настройки прокси или памяти, которые ставил кто-то до вас.

**Docker (`atlassian/jira-software`).** Та же переменная, но как переменная окружения контейнера:

```yaml
services:
  jira:
    image: atlassian/jira-software:9.12
    environment:
      JVM_SUPPORT_RECOMMENDED_ARGS: "-Dtestspot.panel.baseUrl=https://testspot.example.com -Dtestspot.panel.secret=RvE1s0kK7mQpZ2xL9dTn4uWbY6hJ8aCf"
```

Правка `setenv.sh` внутри контейнера не годится: она исчезнет при следующем `docker run` с новым образом.

**Kubernetes, официальный чарт Jira DC.** Аргументы задаются значением чарта (в текущих версиях —
`jira.additionalJvmArgs`, списком) либо той же переменной через
`jira.additionalEnvironmentVariables`. Точное имя ключа сверьте со `values.yaml` своей версии чарта: он
меняется между мажорными, и это единственный пункт этой инструкции, который зависит не от нас.

**Windows, Jira как служба.** Аргументы службы, а не файл: запустите
`<каталог-установки>\bin\tomcat9w.exe //ES//JIRA` (имя службы — как у вас в services.msc), вкладка
**Java** → поле **Java Options**, **по одной опции на строку**:

```
-Dtestspot.panel.baseUrl=https://testspot.example.com
-Dtestspot.panel.secret=RvE1s0kK7mQpZ2xL9dTn4uWbY6hJ8aCf
```

Если Jira на Windows запускается не службой, а из консоли — `bin\setenv.bat`, строка
`set JVM_SUPPORT_RECOMMENDED_ARGS=...`, без кавычек.

**Data Center с несколькими нодами.** На **каждой** ноде. Нода без свойств отдаёт «не настроено» тем
пользователям, кого балансировщик привёл на неё, — то есть примерно каждому N-ному, и это самый
неприятный вид «иногда не работает».

**Перезапустите Jira.** Проверить, что свойства доехали: ⚙ → **System** → **System Info** →
*JVM Input Arguments*, там должны быть обе строки.

## Шаг 4. Проверить и подключиться

1. Откройте любой тикет. В правой колонке появится блок **TestSpot**.
2. Первый раз он предлагает **Connect TestSpot**. Нажмите — откроется новое окно на TestSpot.
3. Войдите там под своей учётной записью и подтвердите запрос.
4. Панель показывает привязанные к тикету тест-кейсы с последним результатом, релевантные прогоны и
   открытые дефекты, и позволяет запустить прогон.

Подключается **каждый человек сам**, один раз на браузер. Так сделано намеренно: панель работает от
персонального токена, поэтому права в TestSpot и запись в аудите — того человека, который смотрит, а не
общей сервисной учётки. Токен лежит в `localStorage` origin'а TestSpot; очистка данных сайта, другой
браузер или приватное окно означают повторный Connect — это ожидаемо, а не поломка.

## Если что-то не так

Отказы подключения панель **намеренно** не объясняет: сообщение с причиной здесь было бы подсказкой для
того, кто подбирает код. Причину пишет лог TestSpot (`api`, компоненты `panel-context` и `panel`) — при
разборе смотреть надо туда, а не на экран.

| Симптом | Причина | Что сделать |
|---|---|---|
| Блока TestSpot в тикете нет совсем | плагин не установлен или выключен | Manage apps → плагин в состоянии Enabled |
| «TestSpot is not configured on this Jira: set the … system properties» | свойства не доехали до JVM | System Info → JVM Input Arguments; на всех нодах; перезапуск |
| «TestSpot needs a signed-in user and an issue to show anything here» | тикет открыт анонимно | залогиниться в Jira |
| Пустой прямоугольник, в консоли браузера `Refused to frame …` | `JIRA_FRAME_ANCESTORS` не содержит origin вашей Jira | шаг 1, затем перезапуск `frontend` и проверка через `curl` |
| Панель рисуется, Connect отвечает «not configured for Data Center» (503) | `PANEL_CONTEXT_SECRET_DC` пуст или короче 32 символов | шаг 1, перезапуск `api` |
| Connect открывает окно, подтверждение проходит, панель не подключается, причина не названа | секреты на двух сторонах различаются, либо часы Jira и TestSpot разъехались | сверить секреты; сверить время (допуск — минута, подпись живёт 10 минут); смотреть лог TestSpot |
| Панель просит Connect заново | токен из `localStorage` пропал: другой браузер, приватное окно, очистка данных сайта | подключиться ещё раз |
| Ссылки из панели ведут не на ваш стенд | не задан `APP_BASE_URL` | шаг 1 |

## Что уходит из Jira

В подписанном адресе iframe: ключ тикета, идентификатор инстанса Jira (server ID), ключ пользователя и
две метки времени. Ни текста тикета, ни полей, ни вложений. Подпись — HS256 общим секретом, живёт
десять минут, дольше пятнадцати TestSpot не принимает в принципе.

Плагин не создаёт таблиц в базе Jira и ничего в ней не хранит. В лог Jira он пишет только при ошибке
подписи.

## Обновление и удаление

- **Обновить:** тот же **Upload app** с новым jar. Ключ плагина тот же, поэтому это обновление, а не
  вторая копия.
- **Удалить:** Manage apps → **Uninstall**. В Jira следов не остаётся; настройки — это две JVM-опции,
  их можно убрать при следующем перезапуске.
- **Отозвать доступ человека:** в TestSpot, в его персональных токенах или через администратора
  TestSpot. Плагин токенов не выдаёт и не видит.

## Чего в этом плагине нет

**Комментарий в тикет при завершении прогона** — отдельная функция TestSpot, к плагину отношения не
имеющая. Настраивается на стороне TestSpot: креденшл трекера в админке (`/api/admin/issue-trackers`) и
галка в настройках трекера у проекта. По умолчанию выключена. Искать её в Manage apps не нужно.
